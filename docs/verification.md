## 0.4.0：Harness 行为验证

2026-09-15：`npm run check` 通过 13 个测试文件 / 92 项测试；真实 VS Code 回归通过。

`node scripts/test-harness-live.mjs` 使用固定 Harness 注释、函数开头及导出后缀，通过真实 DeepSeek 和生产 CompletionEngine 分别执行 JSON、SSE；生成结果能够解析并实例化，接收两组不同文本并返回不同字符串。当前样例实现为回显响应和简单历史记录，验证的是最小输入/输出行为，不是完整 LLM 智能体。每次响应 7 行，服务返回输入 197 / 输出 63 / 总计 260 token；两次合计 520 token。报告和生成样例位于忽略的 artifacts 目录，测试密钥只通过进程环境传入。

协议测试确认官方需求注释路由 Chat、关闭 thinking、仅一个请求、SSE delta 与 usage 正确解析，普通续写及自定义端点保留 FIM。过滤测试覆盖用户示例中的元数据扩写、重复块及混合围栏，并保留明确的包元数据需求。质量规则不保证发现所有逻辑错误。

## 0.3.2：延迟优化

2026-09-15：`npm run check` 通过 11 个测试文件 / 62 项测试；真实 VS Code 宿主回归通过，包含 Python TODO 多行接受及项目联动。

`node scripts/benchmark-completion.mjs` 固定模拟检索 80ms、Provider 40ms，5 次样本：旧版串行调度模拟中位数 442.77ms，当前引擎中位数 200.10ms，引擎缓存命中中位数 0.04ms。旧版为按旧顺序的计时模拟，不是启动旧安装包测量；这些数值不包含真实模型、编辑器绘制，缓存数据也不包含前置检索，不能当作端到端灰字延迟承诺。

## 0.3.0：项目感知与局部联动

2026-09-15，`npm run check` 通过 10 个测试文件 / 53 项测试，类型检查和生产构建通过。

真实 VS Code 1.107.1 宿主中额外验证：

- `api.ts` 未打开时，在其他文件输入 `fetchAcc` 返回 `fetchAccount` 项目候选和导入建议。
- 函数形参重排后，生成绑定到同一声明的跨文件调用更新；连续接受两处更新后得到正确实参顺序。
- 同文件配置值由 `100` 改为 `2000`，相邻两处得到建议；接受第一处后，第二处位置正确重定位。
- 真实 DeepSeek 请求携带未打开文件中的 `fetchAccount` 签名和说明，接受模型补全后生成对该项目函数的调用。
- GhostTextAcceptanceTracker 单元测试覆盖文档事件先于命令回调、最小化替换、CRLF、多行、部分接受及非匹配编辑。
- 防误改测试覆盖其他模块的同名函数、纯形参重命名、具有副作用的参数、调用后才定义的变量、临时不完整签名及跨作用域同名对象。

`node scripts/benchmark-project.mjs` 的本机合成数据：1001 文件 / 1000 导出符号，构建 382ms；40 次本地热查询中位数 0.62ms，P95 1.8ms。数据不包含远端模型延迟，也不能作为真实大型项目的性能保证。

测试目录和报告仍在忽略的 `artifacts/` 内。测试 Key 没有写入源码、配置或安装包。项目结构化分析当前覆盖 TS/JS；其他语言、复杂 tsconfig 继承和通用模型 Next Edit 不在本轮验收范围内。
